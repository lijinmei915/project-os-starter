# 错误模式记录

> 用途：记录错误复盘和新增约束，回答“踩过什么坑、以后怎么避免”。
> 什么时候更新：误删、误改、误判、测试跑偏、规则失效时。
> 不要写什么：成功经验、普通进展、重复的 changelog 内容、当前状态摘要。
> 每次犯错后立即记录。
> 格式：犯的错 / 根本原因 / 加了什么规则。

### 2026-07-24 目标验收不能只信任 activeGoalId 指针

**犯的错**：目标面板能够从目标列表回退显示当前可操作目标，但“验证目标”和“确认完成”直接传递 `snapshot.goals.activeGoalId`。历史或投影状态缺少该指针时，Tauri 收到 `goalId: null` 并在验收开始前报参数错误。

**根本原因**：同一 UI 对“当前目标”使用了两套解析规则：展示层会回退，执行层只读取易缺失的状态指针；客户端也没有在调用 Tauri 前拒绝空目标 ID。

**加了什么规则**：所有目标执行操作必须复用 `resolveWorkspaceGoal` 取得可操作目标 ID，并在客户端阻断空 ID、给出可执行提示；不得把缺失状态指针透传为 Tauri 参数。涉及同一操作的验证与确认路径必须一起覆盖回归。

### 2026-07-23 已批准工具在消费前必须重新校验项目绑定

**犯的错**：Agent Run 审批记录保存了 `projectId`，但旧执行命令只对当前选中项目做权限校验。用户在审批后切换项目时，已批准的 Patch 或检查可能被重定向到另一个项目。

**根本原因**：将 approval token、allowed files 和 access mode 视为完整授权边界，漏掉了“审批对象所属项目”这个不可变主体；Tauri command 直接重新解析 current project，也让这个缺口没有在 Execution 领域集中校验。

**加了什么规则**：任何已批准写入或检查必须在消费 approval 前比对 `AgentRun.projectId` 与实际执行项目 ID；不一致时零写入、零状态转换并保留原审批。项目绑定、token、工具参数和权限必须在同一 Execution 边界中完成再验证。

### 2026-07-21 WebDriver feature 专用 Runtime 代码必须按 feature 编译

**犯的错**：为原生多文件恢复 fixture 增加审批证据时，在 `append_evidence(&mut run, ...)` 调用中同时读取了 `run.checkpoint.allowed_files`。默认 `cargo check` 没有编译该 `#[cfg(feature = "webdriver")]` 分支，直到原生 smoke 启动时才暴露 Rust 借用冲突。

**根本原因**：把默认 crate 编译当成了所有条件编译路径的验证，遗漏了 native smoke 实际启用的 WebDriver feature。

**加了什么规则**：修改 `#[cfg(feature = "webdriver")]` 的 Runtime 或测试 fixture 后，必须运行 `cargo check --manifest-path desktop/src-tauri/Cargo.toml --no-default-features --features webdriver`，再运行 `npm --prefix desktop run test:native`；所有对可变对象的证据 payload 必须在取得可变借用前先复制所需字段。

### 2026-07-20 共享 Rust 源文件改依赖后必须验证所有消费 crate

**犯的错**：状态命名空间迁移让共享 `repository.rs` 依赖 `crate::runtime::state_namespace`，Desktop Rust 回归全部通过，但通过 `#[path]` 复用该文件的旧 CLI 没有同名模块结构，导致全仓库测试中的 CLI 构建失败。

**根本原因**：验证范围只覆盖了定义模块的 Desktop crate，没有盘点同一源文件被哪些其他 crate 直接引入；Rust 源文件复用隐藏了跨 crate 的编译依赖。

**加了什么规则**：修改任何被 `#[path]`、`include!` 或 workspace 多 crate 复用的 Rust 文件前，先搜索全部消费者；依赖路径变化后必须逐个运行消费 crate 的测试。迁移期兼容桥应显式提供相同模块形状，长期则删除源码级跨 crate 复用或抽成独立 library crate。

### 2026-07-20 脏工作树中的共享 Rust 大文件不能直接全文件格式化

**犯的错**：为格式化新增的状态迁移代码，直接对已有大量未提交改动的 `runtime/app.rs` 运行 `rustfmt`，把本轮范围外的旧代码也做了机械重排，扩大了差异。

**根本原因**：把“格式化命令可以机械执行”误解成“可以忽略脏工作树的文件所有权和差异范围”；共享大文件并不具备独立格式化边界。

**加了什么规则**：脏工作树中的共享文件只格式化本轮新增且独立拥有的文件；对已有用户改动的大文件必须手工保持局部格式，先比较 `git diff --numstat` 再决定是否运行 formatter。若误触发，使用 HEAD 基线加忽略空白的语义差异重建，恢复范围外格式并再次运行编译与回归。

### 2026-07-20 终端会话重启前必须显式告知终止边界

**犯的错**：修复 PTY 生命周期后触发桌面 Rust 热重启，用户未关闭的嵌入终端会话被回收，界面只显示新建的 `main` 会话。

**根本原因**：当前终端会话、屏幕缓冲与 tab 列表仅存在应用内存；进程重启后既不能恢复 PTY，也没有持久会话后端。此前没有在重启前明确提示这一限制。

**加了什么规则**：开发重启或应用升级前必须明确告知会终止多少临时终端会话；不得把会话销毁描述为无影响的热更新。持久终端必须作为独立能力通过受控 session service 或可选 terminal multiplexer 实现，不能默认把终端输出落盘。

### 2026-07-20 PTY 会话关闭必须终止进程组

**犯的错**：桌面终端关闭或重启时只调用 PTY shell 的 `child.kill()`。Codex、Code host 和后台任务作为 shell 的派生进程继续运行，用户关闭 tab 后仍看到任务卡在 `Working`，会话也无法真正删除。

**根本原因**：`portable-pty` 为每个会话建立独立 Unix session，但终止逻辑没有向该 PTY 的前台进程组发送信号。

**加了什么规则**：关闭或重启终端必须先终止 PTY 的独立前台进程组，再结束 shell；`Ctrl-C` 只负责中断当前命令，关闭 tab 负责回收整个会话。不得用替换前端终端组件掩盖后端进程生命周期缺陷。

### 2026-07-20 Codex hook 不能引用其他项目的绝对路径

**犯的错**：OmniDesk 的 `.codex/hooks.json` 仍指向 `project-starter-pack` 的 hook 脚本。终端内 Codex 调用工具时得到 `PreToolUse hook exited with code 127`，任务停在 `Working`，但终端输入区已出现。

**根本原因**：接入时复制了另一个项目的绝对路径；目标项目虽然拥有同名本地脚本，配置没有同步改写。

**加了什么规则**：项目 hook 一律使用项目根目录可解析的相对路径，如 `bash .codex/hooks/<name>.sh`。接入或迁移后必须校验 JSON，并从目标项目根目录实际执行所有 hook；不得把其他项目的绝对 hook 路径带入运行配置。

### 2026-07-20 原生 WebDriver 的隔离端口不能被误判为浏览器 Preview

**犯的错**：原生 WebDriver 使用独立 Vite 端口 `1422`，但运行时只把 `1420` 识别为桌面开发窗口，导致测试构建静默走 Preview 分支，终端会话没有真正启动。

**根本原因**：运行时来源判断把“loopback 非 1420”直接等同于浏览器 Preview，没有区分“带 Tauri bridge 的测试 WebView”和普通浏览器。

**加了什么规则**：专用 `1422` 端口仅在检测到 Tauri bridge 时作为原生 WebDriver Runtime；没有 bridge 的页面仍保持 Preview 只读边界。原生 smoke 必须断言终端生命周期已启动，不能仅验证输入控件。

### 2026-07-20 原生 WebDriver 不能只等待服务端口

**犯的错**：首版 macOS 原生 smoke 在 WebDriver `/status` 返回 ready 后立即定位 React 控件，偶发得到 `Unable to locate element`。

**根本原因**：嵌入式 WebDriver 的 HTTP 服务先于 WKWebView 中的 Vite / React 首屏渲染完成；服务可连接不代表应用交互树已经存在。

**加了什么规则**：原生 UI 测试必须分别等待 driver ready 和目标控件可定位，控件等待使用有界重试；不能以端口或窗口创建作为页面可交互的证据。

### 2026-07-20 测试 feature 的 permission 不能进入默认 capability

**犯的错**：把 `wdio-webdriver:default` 写入默认 capability 后，未启用 WebDriver feature 的辅助二进制解析不到该 permission，导致 patch normalizer 回归构建失败。

**根本原因**：测试插件的 permission metadata 只会在插件 feature 编译时注册，默认 capability 却对所有二进制和 feature 组合生效。

**加了什么规则**：测试专用插件默认不得向通用 capability 注入 permission；只有插件确实通过前端 command 权限提供能力时，才为测试构建提供专用 capability。嵌入式 HTTP WebDriver 不需要 Tauri command permission。

### 2026-07-20 Tauri CLI 不能由原生 smoke 直接终止

**犯的错**：原生 WebDriver smoke 直接终止它启动的 Tauri CLI 后，调用测试的 Node 进程也被连带终止，成功日志和失败错误都无法可靠返回。

**根本原因**：Tauri CLI 会管理 dev server 与应用子进程，并在收到终止信号时清理其进程组；测试进程不能假设它是独立的普通子进程。

**加了什么规则**：原生 smoke 在完成 WebDriver session 后按子进程树从叶到根关闭 Tauri CLI、Vite 与应用进程，再移除临时夹具；不得向进程组广播终止信号，主测试进程必须先正常返回结果。

### 2026-07-20 嵌入式 macOS WebDriver 的终端覆盖必须先完成最小复现

**犯的错**：OmniDesk 的终端 tab 在嵌入式 WebDriver 会话中中断后，过早将它归因为插件与 xterm 的通用兼容性问题。

**根本原因**：独立的 Tauri+xterm，以及 Tauri+xterm+React/Radix Tabs 夹具均可通过相同 W3C click，说明问题仍在 OmniDesk 的终端生命周期、事件订阅或工作台组合中，不能据此向上游提交问题。

**加了什么规则**：不能为迁就测试驱动而改变生产终端的焦点、尺寸或 PTY 行为，也不能在最小夹具无法复现时向上游报错。原生自动化只覆盖已稳定的工作面；终端、审批、取消与恢复继续通过 Native Core 的隔离 fixture 状态机回归验证，后续按 OmniDesk 生命周期逐层拆分。

### 2026-07-20 新增辅助二进制后必须声明桌面默认启动项

**犯的错**：新增 `omnidesk-patch-normalizer` 后，`tauri dev` 执行 `cargo run` 无法判断应该运行桌面应用还是辅助二进制，桌面端直接退出。

**根本原因**：Cargo package 有多个 `[[bin]]`，但没有 `default-run`；单元测试和 `cargo check` 都不会覆盖 Tauri 的默认启动选择。

**加了什么规则**：桌面 package 新增任何辅助 binary 时，必须在 `Cargo.toml` 固定主应用 `default-run`，并至少实际启动一次 `npm run dev` 验证主窗口进程能运行。

### 2026-07-19 Eval suite 必须从自身脚本目录调用 runner

**犯的错**：首次启动真实 12-case suite 时，runner 被按 `desktop/run-agent-eval-*.mjs` 查找，导致在模型请求前直接报 `MODULE_NOT_FOUND`。

**根本原因**：suite 的工作目录是 `desktop/`，却没有把子 runner 的 `scripts/` 前缀作为进程参数传入。

**加了什么规则**：评测编排器必须用仓库相对路径显式调用 `scripts/` 下的 runner，并在 CI 前先执行一次无 Provider 的路径/入口 smoke check；入口错误不能计入模型能力失败。

### 2026-07-19 npm prefix 下的 Eval 路径参数必须相对 desktop

**犯的错**：从仓库根目录通过 `npm --prefix desktop run check:agent-eval` 传入 `desktop/evals/...`，脚本按 desktop 工作目录解析成了 `desktop/desktop/evals/...`。

**根本原因**：混用了仓库根目录路径和 npm prefix 后的脚本工作目录。

**加了什么规则**：所有 `desktop` npm script 的路径参数统一相对 `desktop/` 目录；CI 使用 `evals/agent-eval-report.json`，需要仓库根目录路径时才显式传绝对路径。

### 2026-07-19 Eval verifier 必须检查语义等价而不是单一字符串

**犯的错**：Provider 校验 case 的 verifier 只查找 `https://`，把合法的 `new URL(value).protocol === 'https:'` 判为失败。

**根本原因**：测试断言绑定了某一种代码写法，而不是任务要求的行为。

**加了什么规则**：Eval verifier 优先检查行为和语义结果；文本断言只能作为辅助，不能把合法实现限制为单一表达式。

### 2026-07-19 Provider 配额错误不能计入 Agent 能力回退

**犯的错**：直接用默认 Provider 跑真实 suite，所有模型 case 都返回空草稿，若只看汇总指标会误以为 Patch 生成能力回退。

**根本原因**：默认 Gateway 返回 `HTTP 403 subscription quota insufficient`，但 Hermes 进程仍以退出码 0 结束，失败只体现在 usage 与 trace 的 `completed: false` / 空输出中。

**加了什么规则**：真实 Eval 必须先做一次最小真实 prompt 连通性验证；runner 支持受保护环境通过 `OMNIDESK_AGENT_EVAL_API_KEY_ENV` / `OMNIDESK_AGENT_EVAL_MODEL` 临时覆盖 Provider，不改工作区配置。配额、认证和网络失败必须保留 trace 并阻断基线更新，不能把空草稿当作模型能力指标。

## 编辑操作

### 2026-07-19 Patch 安全校验必须覆盖 Rust 原生审批链

**犯的错**：Node Tool Gateway 已拒绝 `.env*` 和目录逃逸 diff，但 Rust Hermes ACP loop 在创建审批时没有执行同一校验，批准后的原生路径会直接将 diff 交给 `git apply`。

**根本原因**：将 Preview / Node Gateway 的输入校验误当作桌面原生 command 的安全边界，Native adapter 没有独立验证外部模型返回的 patch header。

**加了什么规则**：每个能创建 Patch approval 或调用 `git apply` 的入口都必须验证完整 header 对、相对路径和 `.env*` 保护；安全评测必须至少覆盖真实 Native path，不能只以 Node Gateway 的拒绝结果作为桌面安全结论。

### 2026-07-19 Diff 路径校验不能只防越界，还必须拦截敏感文件

**犯的错**：Agent Tool Gateway 对 `apply_patch` 的 diff header 只校验了路径是否逃出项目根目录，`.env` 虽位于根目录内却仍被错误地生成审批请求。

**根本原因**：路径安全策略只复用了 traversal 规则，没有与 Native 工具层的敏感文件边界对齐。

**加了什么规则**：所有 Patch header 都必须同时经过“相对路径”与“敏感路径”校验；`.env*` 必须在创建 approval 前直接拒绝。安全 Eval 必须断言结果为 `denied`，不能把“模型没有输出”当作产品安全证据。

### 2026-07-19 有写入副作用的 CLI 验证必须使用隔离夹具

**犯的错**：验证 CLI `state sync` 时将仓库根目录作为 target，临时改写了真实 `.project-os/state.json` 并生成事务、事件和 bundle 产物。

**根本原因**：把“本地验证”误判为只读检查，未先根据命令语义确认它会对 target 持久化。

**加了什么规则**：所有 CLI 验证先按写入语义分类；会落盘的 `state sync`、`scan`、`report`、`run` 必须在独立临时夹具运行。若误写工作区，只能精确恢复自己改变的字段和本次生成的已知产物，禁止覆盖用户同文件的其他改动。

### 2026-07-19 状态记录的读取路径必须复用写入路径校验

**犯的错**：Agent Run 写入时校验了 id，但读取时直接把 id 拼进文件路径；恢复、审批和执行入口因此没有与持久化保持同一安全边界。

**根本原因**：只把路径校验理解为写入保护，遗漏了读取同样会泄露或越界访问项目外状态。

**加了什么规则**：任何持久化实体的 `load / get / delete / resume` 都必须经同一个 relative-path helper；禁止一侧校验、另一侧直接 `join`。对 `..` 和嵌套路径必须有回归。

### 2026-07-19 Agent Run 审批状态不能抢先离开执行门

**犯的错**：审批动作将 Agent Run 从 `awaiting-approval` 直接写为 `queued`，而受控工具执行入口仍只接受 `awaiting-approval`，导致已批准的 Patch 或检查无法执行。

**根本原因**：把“审批已完成”和“工具已调度”混为同一个 Run 状态，未将 approval 子状态与 Run 生命周期分离。

**加了什么规则**：审批仅更新 approval 的 `status: approved` 和一次性 token；Run 在工具真正消费审批前保持 `awaiting-approval`。每一个状态迁移必须由下一条 command 的 guard 反向验证，且覆盖“审批后可执行”的回归。

### 2026-07-18 Hermes ACP 健康检查通过不代表 Provider 凭据可用

**现象**：`hermes-acp --check` 和 ACP `initialize / session/new` 均成功，但真实 `session/prompt` 返回 HTTP 401 Invalid token。

**根本原因**：ACP 通道健康检查只验证本地协议和适配器可启动；真实模型请求还依赖当前 OmniDesk Provider 的 Key、模型和网关认证。直接运行 Hermes 还可能读取旧的默认模型配置。

**加了什么规则**：Hermes 状态只能标记 ACP 通道可用，不能标记模型可执行；执行前必须同步当前 Provider 的非敏感运行配置，并用真实 prompt 做凭据验证。401、配额和网络错误必须进入失败/降级分支，不能生成“已完成”或伪造执行结果。

### 2026-07-18 对话动作不能脱离 pendingAction 独立恢复

**现象**：历史对话显示“生成改动草稿 / 查看执行”按钮，但记录中的 `pendingAction` 已为空，点击生成按钮没有任何进展或错误反馈。

**根本原因**：旧记录迁移只保留了 `turn.actions`，没有校验动作所依赖的任务、请求和待确认状态是否仍完整；UI 因此渲染了不可执行的幽灵动作。

**加了什么规则**：恢复对话时必须同时验证 action、task、request 和 pendingAction 契约；依赖缺失的动作必须移除或重建，不能继续显示。动作点击返回 false 时必须给用户明确反馈，不能静默失败。

### 2026-07-18 Tauri registry 命令参数必须统一使用 input 包装

### 2026-06-04 抽 tokens.css 后 tab 滑块动画失效

**犯的错**：把 `--transition-normal: .25s ease` 抽进 `tokens.css` 后，tab 滑块的平滑滑动消失了，点击瞬间硬跳。

**根本原因**：滑块用了 `transition: transform var(--transition-normal, .3s) cubic-bezier(.4,0,.2,1)`。token 值自带 `ease` 关键字，展开后变成 `transform .25s ease cubic-bezier(...)` —— 一条 transition 里出现两个缓动函数（`ease` 和 `cubic-bezier`），整条声明非法被浏览器丢弃，退化成无动画。抽 token 前 token 未定义，走 `.3s` 兜底，反而合法。

**加了什么规则**：
- transition 速记里如果还要单独指定缓动曲线，时长 token 只放纯时长（如 `.25s`），不要把 `ease` 等缓动关键字塞进时长 token。
- 改动共享 token 后，必须回归所有引用该 token 且自带缓动函数的动画。
- 滑块改回 `transition: transform .3s cubic-bezier(.4,0,.2,1)`，不复用含缓动关键字的 token。

### 2026-06-04 选中态样式多次漂移、与基准卡片不一致

**犯的错**：Q1/Q2 向导卡片和代码来源卡片的选中态被反复改成 teal 绿边框 + box-shadow ring，和「生成工程契约」下的 kit-option 基准卡片（中性深色 1px 边框）不一致；滑动时被点击按钮还闪白底。

**根本原因**：（1）没有把「选中态视觉」当成一套统一规范，每次单独调一个组件就漂移；（2）box-shadow ring 叠在 1px border 上视觉变粗；（3）`button:hover` 白底没排除 `.is-active`，滑动途中和滑块叠加闪白。

**加了什么规则**：
- 选中态以 kit-option 为基准：`border-color: --color-surface-inverse` + `background: --color-surface-panel`，1px 边框、无 box-shadow ring。

- 任何“恢复浏览器预览”动作先执行 `npm --prefix desktop pkg get scripts.web:dev` 或读取已确认的脚本映射，再启动进程；不能凭上一轮记忆拼命令。

### 2026-07-12 同一计划请求由多个状态源独立收口导致结果互相矛盾

**犯的错**：计划生成同时由手工超时计时器、Promise 超时、任务投影和对话消息分别更新状态，导致一次请求先显示超时失败，迟到的成功结果又创建任务并显示等待执行。

**根本原因**：缺少请求级唯一标识和单一终态提交规则；对话层还重复投影了执行层已经展示的任务状态。

**加了什么规则**：
- 每个异步用户请求必须有唯一 `requestId`，并且只能从 `running` 进入一次终态。
- 超时或取消后必须使底层请求失效；迟到的成功、失败结果不得再写对话或创建任务。
- 超时只包围可放弃的远程生成阶段，不得包围已经开始产生本地副作用的任务持久化阶段。
- 新任务必须先完成耐久写入再进入 UI；已有任务状态可乐观更新，但必须提供近场持久化错误。
- 任务创建接口必须按 `requestId` 幂等，且去重检查必须扫描完整存储，不能受 UI 列表分页或最近记录截断影响。
- 幂等实体应优先由请求键派生稳定 ID；仅靠“先查再写”仍有并发竞态，扫描去重只能作为兼容层。
- 任务和 manifest 等运行时状态文件不得直接覆盖写入；必须使用同目录临时文件、flush/sync 和原子替换，失败时清理临时文件。
- 多文件无法组成单一原子事务时，读取端必须以真实实体文件为兜底合并索引，确保“实体已写入、索引未更新”仍可恢复。
- 存储恢复不得立即删除未知残留：临时文件需经过陈旧阈值后清理，损坏实体应隔离并保留原名和时间供诊断。
- 异步任务链路必须让对话结果与持久化实体共享 `requestId`，并由存储端记录真实 `persistedAt` 与运行面，不能由 UI 推测落盘成功时间。
- 助手不得只用自然语言承诺后续动作；承诺必须绑定机器可读 `pendingAction`，短确认应消费该动作而不是重新进入聊天路由。
- 消息幂等不能只依赖任务幂等：提交入口还需防重入、短窗口内容去重和持久化 `submissionId`。
- 对话 Action 必须携带目标实体 ID，并且只有底层动作成功后才能消费 pending action；仅修改状态却不切换工作面或提供反馈，会让有效点击看起来像失效。
- 远程计划生成超时不能阻断已有本地确定性计划；超时应降级并标记 trace，而不是让用户为 provider 延迟承担失败。
- 处理中状态必须由执行器推送真实阶段事件；不能在运行时只显示一个静态标签、结束后才补齐步骤详情。
- 同一请求的处理前、处理中和完成后必须共用一份稳定阶段定义；不得在各展示态分别手写步骤数组。
- 处理摘要必须从时间线的唯一 `current` 事件推导，后续事件必须按稳定 id 合并并持久化，不得用独立 label 或整组替换造成摘要、当前步骤与历史不一致。
- 不得把所有行动意图压成笼统 `task -> generate plan`；必须先解析具体 capability，再按风险与副作用决定直接执行或等待确认。
- 按钮和回复承诺必须对应真实 executor；“开始执行”不得只修改状态，“运行检查”不得转入生成改动链路。
- 对话状态、意图、动作、投影和存储不能继续堆在页面提交函数里；新行为必须先进入 Conversation Runtime 纯函数契约，再由 Workbench 调用。
- 对话只展示该请求的一次结果，持续任务状态由执行页和任务栏承载，不在对话中自动重复投影。

### 2026-07-13 取消计划只清运行状态但没有结束全局反馈

**犯的错**：桌面端点击“停止生成”后，对话已经显示取消，Composer 也恢复可输入，但右下角 Action Feedback 仍持续显示“正在生成计划”，形成相互矛盾的状态。

**根本原因**：`stopPlanGeneration` 只清理 `activePlanRequestRef` 和 `planLoading`，没有用同一个 `requestId` 结束 `generate-plan-{requestId}` 对应的全局反馈。

**加了什么规则**：
- 一个请求的对话 turn、Composer loading、执行 ref 和全局 Action Feedback 必须按同一 `requestId` 一起进入终态。
- 取消路径必须显式结束 running feedback；不能依赖异步请求的 `finally`，因为请求失效后 `finally` 会主动放弃旧请求的 UI 写入。
- 并发交互的桌面 smoke 必须同时观察对话内容、输入按钮和全局反馈，不能只验证其中一个表面。

### 2026-07-13 组合 AppleScript 前没有先验证最小点击命令

**犯的错**：首次桌面 smoke 把激活窗口、坐标点击、键盘输入和截图合并进一段 heredoc AppleScript，解析阶段报错，导致该次操作没有执行。

**根本原因**：没有先用最小 `System Events click at` 命令验证当前系统支持的脚本语法，就直接组合多步桌面操作。

**加了什么规则**：
- Tauri WebView 未暴露 Accessibility 控件时，先单独验证窗口坐标和一次最小点击，再组合输入与截图。
- 桌面 smoke 的组合脚本一旦解析失败，先确认窗口状态未改变，再切回可验证的单步命令；不要重复执行同一失败脚本。
- 热重载、会话恢复或已有草稿存在时禁止用坐标直接提交；必须先通过 Accessibility 精确定位输入控件，并读取确认输入值就是本轮测试文本。
- 误提交后立即停止后续点击，按本轮生成的 `conversationId / requestId / taskId` 精确清理测试产物，不得删除同名历史记录。
- 所有桌面 smoke 操作前必须显式把 `OmniDesk` 设为 frontmost；输入优先直接设置 OmniDesk `AXValue`，禁止依赖全局剪贴板和通用键盘焦点。
- 需要临时改剪贴板时，恢复动作必须在任何校验失败或提前返回之前执行；不得用会跳过恢复代码的 AppleScript `error` 分支。
- 不得自动化宿主 ChatGPT/Codex 输入框。发现跨应用输入污染时立即停止 smoke、清理未提交草稿，并记录具体影响。
- 启动桌面端前先读取 `desktop/package.json` scripts，使用仓库定义的 `npm --prefix desktop run dev`；不得猜测 script 名，也不得用裸 debug binary 替代 `tauri dev`。
- zsh 脚本不得把 `status` 当普通变量；轮询状态使用 `task_state` 等非保留名。

### 2026-07-15 写锁并发测试误用 1 秒陈旧阈值

**犯的错**：写锁并发测试把项目配置的 `staleLockSeconds` 设为 1 秒。`cargo run` 启动超过 1 秒时，刚创建的并发锁会被当成陈旧锁清理，导致“并发写入必须拒绝”用例错误通过写入路径。

**根本原因**：同一个极短阈值同时承担正常并发锁和陈旧锁两种相反语义，测试结果受编译缓存与机器负载影响。

**加了什么规则**：
- 正常并发锁用例使用足够覆盖命令启动时间的阈值，当前为 30 秒。
- 陈旧锁回收用例继续用历史时间戳，并通过命令行显式传 `--stale-lock-seconds 1`。
- 并发拒绝与陈旧回收必须使用不同 fixture 条件，不能依赖命令恰好在一秒内启动。

### 2026-07-14 Apply 前 trim diff 导致合法补丁损坏

**犯的错**：Rust `apply_patch_draft` 对 unified diff 调用 `str::trim` 后再传给 `git apply`，把最后一行必需的换行符删除，真实 Apply 在校验阶段报 `corrupt patch at line 4`。

**根本原因**：把“判断字符串是否为空”和“规范化实际补丁内容”混成一步，没有把 diff 当作需要字节级保真的执行输入；原有测试只覆盖任务存储，没有用真实 `git apply` 验证补丁。

**加了什么规则**：
- diff 只能用 `trim()` 判断是否为空，传给校验和应用命令的内容必须保留原始字节与末尾换行。
- Apply 回归测试必须同时执行 `git apply --check` 和真实 `git apply`，并核对最终文件字节。
- Apply 校验失败必须把错误写入任务 `applyResult`；Apply 已成功但验证异常时保留成功 Apply 结果，并把原因写入 `verificationSummary`。

### 2026-07-16 Preview 目标更新遗漏当前项目路径

**犯的错**：浏览器预览的目标验收状态更新直接引用未定义的 `projectRoot`，并沿用仓库根目录写入 helper；切换工作区项目后，更新会失败或写向错误项目。

**根本原因**：新增多项目读写路径后，只迁移了创建、切换和确认目标，遗漏了既有验收状态更新函数，没有让所有治理写操作统一从 registry 解析当前项目。

**加了什么规则**：
- Preview 内所有项目治理读写函数必须在函数入口调用 `currentPreviewProject()` 获取 `projectRoot`。
- 目标、任务和验收等项目数据必须使用 `readJsonAt` / `writeJsonAt`，不得混用固定仓库根目录 helper。
- 多项目写入回归至少覆盖创建、确认、切换和状态更新四类路径。

### 2026-07-16 阶段目标关联未校验却显示成功

**犯的错**：对话确认阶段目标后，无条件回复“已关联当前项目目标”，但实际新目标缺少 `parentProjectGoalId`，项目目标的 `stageGoalIds` 也没有对应 ID。

**根本原因**：前端只判断创建和确认 command 是否返回，没有读取写入后的目标关系验证结果；snapshot 又没有暴露项目目标 registry，界面只能展示无法核实的泛化文案。

**加了什么规则**：
- 治理写操作的成功文案必须来自写后返回数据，不得根据预期流程推断成功。
- 创建阶段目标后必须同时验证 `parentProjectGoalId` 和项目目标反向关联；缺失时显示近场错误，不得进入成功态。
- Workspace snapshot 必须提供项目目标 registry，使对话能够展示实际关联名称，而不是只写“当前项目目标”。
- 对话候选确认采用原位状态更新，保留范围并清空与当前动作无关的模型 references，禁止追加重复成功消息。

### 2026-07-12 内嵌浏览器继承宿主桌面全局导致运行时误判

**犯的错**：仅通过 `window.__TAURI_*` 判断 OmniDesk 是否运行在 Tauri。Codex/ChatGPT 等桌面宿主的内嵌浏览器可能暴露同名全局，导致 `1421` 浏览器预览误走 Tauri command，表现为输入后没有响应。

**根本原因**：把“宿主存在桌面桥”误当成“当前页面属于 OmniDesk Tauri”，没有校验页面来源。

**加了什么规则**：
- 本地开发环境必须同时满足 Tauri bridge 和 OmniDesk dev origin `127.0.0.1:1420`。
- `1421` 等浏览器预览端口即使继承宿主的 `__TAURI_*`，也必须走 Preview API。
- 运行时检测测试必须覆盖普通浏览器、宿主污染的浏览器和真实 Tauri dev origin。

### 2026-05-20 Chrome 截图回归缺少超时保护导致任务挂住

**犯的错**：生成视觉 baseline 时，`tests/screenshot-regression.sh` 调用本机 Chrome 后一直等待，没有及时退出，导致当前任务被卡住。

**根本原因**：脚本直接执行浏览器命令，没有给 headless 截图过程设置超时；一旦 Chrome 启动或截图阶段卡住，回归脚本无法自行恢复。

- Chrome 截图命令不再强制传入临时 `--user-data-dir`，优先使用更接近直接 headless 的稳定参数。
- `docs/ENVIRONMENT.md` 记录 `BROWSER_SCREENSHOT_TIMEOUT` 环境变量。
- `docs/RUNBOOK.md` 增加 Chrome 截图卡住时的复跑方式。

## AI 工程化与成长机制

### 2026-07-17 批量机械重写未固定 locale

**犯的错**：删除已迁出的会话镜像实现时，直接调用 Perl 进行有边界的机械重写；本机的 `C.UTF-8` locale 不可用，命令在修改前失败。

**根本原因**：把工具执行环境的 locale 当成可用前提，没有为一次性机械重写显式提供稳定 locale。

**加了什么规则**：
- 需要调用 Perl 等文本工具做机械改写时，先使用 `LC_ALL=C LANG=C` 固定执行环境；命令失败后先读取源码确认未改动，再重试。
- 同一批机械重写的每一条命令都必须带上固定 locale，不能只给首条命令设置环境变量。
- 机械重写必须以唯一的起止标记限定范围，完成后立刻搜索旧标识并读取相邻源码，再进入构建或测试。

### 2026-07-17 模块迁移后保留旧源码位置断言

**犯的错**：将阶段目标候选的会话投影迁入 Conversation 模块后，已有回归仍断言 `main.jsx` 中的实现细节，导致行为和构建都通过时测试失败。

**根本原因**：迁移时只验证了运行路径与新增模块测试，没有系统检查依赖具体源码位置的边界断言。

**加了什么规则**：
- 移动职责到新模块时，同步搜索旧文件名和旧实现片段的源码断言，改为断言新 owner 与容器注入关系。
- 结构迁移验收必须同时覆盖行为回归、边界回归和生产构建；其中任一失败都不能记录为完成。
- 当测试失败信息指向已迁出的实现文本时，先迁移断言 owner，再重新运行全量测试；不得通过保留旧死代码让断言继续通过。
- 在仓库根目录调用 Desktop npm 命令时必须使用 `npm --prefix desktop ...`；不能假定根 `package.json` 暴露桌面脚本。

### 2026-07-18 对话历史分组必须保留会话所有权语义

**问题**：会话数量增长后，如果只按更新时间平铺，任务对话会和通用项目对话混在一起，用户无法判断一条记录是否会继续影响某个任务上下文。

**根本原因**：列表展示只使用时间排序，没有把已有的 `taskId` 所有权和临时状态过滤规则投影到历史列表层。

**加了什么规则**：
- 任务对话必须单独分组并优先展示；通用对话再按今天、昨天、更早分组。
- 搜索只作用于展示层，至少覆盖标题、预览和 `taskId`，不能改变持久化记录或上下文窗口。
- 带 `archivedAt` 的会话默认隐藏，但归档与恢复必须在后续明确的管理入口中实现，不能把隐藏误当删除。
- 分组、过滤和搜索必须有纯函数测试，且要和构建、桌面 smoke 一起验收。

### 2026-07-18 React hook 注入不能提前读取后声明变量

**问题**：将稍后由 hook 返回的 `generatePatchDraft` 直接用对象 shorthand 注入对话 controller，页面初始化触发 `Cannot access 'generatePatchDraft' before initialization`，浏览器只显示启动失败空态。

**根本原因**：对象装配发生在变量初始化前，shorthand 会立即读取变量；仅仅把调用放进后续 handler 并不能避免 TDZ。

**加了什么规则**：
- 跨 hook 生命周期装配的回调统一使用 `(...args) => handler(...args)` 延迟读取，不能在初始化顺序不确定时使用 shorthand。
- 任何涉及 hook 返回值的装配改动必须先跑 Web build，再跑 Playwright smoke；页面启动失败不能被只读单测掩盖。

### 2026-07-18 密钥扫描正则误报 task 路径

**问题**：`tests/run-tests.sh` 的密钥检查把 `task-conversation-context`、`task-lifecycle-controller` 等路径中的密钥前缀子串误报为 provider key，导致检查在没有真实密钥的工作区失败。

**根本原因**：扫描表达式没有 token 边界，允许普通标识符中的子串触发；它也没有把路径标识和凭据格式区分开。

**加了什么规则**：
- 运行全量测试时若 provider key 为空，使用 `PROJECT_OS_ALLOW_EMPTY_PROVIDER_KEYS=1` 的纯本地模式，并单独记录扫描器误报，不修改业务代码或历史交接内容来规避它。
- 后续修复扫描器时必须增加 token 边界并用真实 key、普通 `task-*` 路径和文档示例做正反例回归。

### 2026-07-16 用归档替代已约定的任务删除

**犯的错**：任务菜单只实现了“归档任务”，却没有实现用户此前明确要求的删除能力，导致用户无法区分“暂时隐藏并可恢复”和“永久移除”。

**根本原因**：为了降低误删风险，擅自用可逆操作替换了已确认的永久操作，没有同时保留两种语义，也没有检查目标和待办关联的清理责任。

**加了什么规则**：
- 归档和删除必须作为两种独立操作：归档可恢复，删除不可恢复，界面文案不得混用。
- 永久删除必须二次确认，并同步删除任务文件、任务清单以及目标和待办中的关联 ID。
- 用户已明确要求删除能力时，不能只提供归档作为替代；若因风险限制不能实现，必须明确说明而不是静默降级。

### 2026-07-16 长任务看板把点击反馈渲染在列表末尾

**犯的错**：任务卡片的“继续推进”只更新选中任务，详情区却渲染在整个任务看板末尾。任务数量较多时视口没有任何变化，用户看到的结果就是按钮点击无反应。

**根本原因**：实现只验证了任务状态已经切换，没有从用户当前视口验证操作反馈是否可见；同时复用了页面底部详情区，却没有滚动、弹窗或区域切换机制。

**加了什么规则**：
- 长列表中的卡片主操作必须在当前视口提供即时反馈，使用近场弹窗、抽屉或明确的视图切换，不能只更新折叠区域或列表末尾内容。
- “继续推进”必须同时说明当前任务、下一步动作和执行结果；运行中任务优先打开任务详情，再由用户触发生成建议、应用改动、验证或交接。
- 交互验收必须真实点击并确认反馈元素可见，不能只检查 React state 或目标组件已渲染。

### 2026-07-16 相邻函数补丁上下文过宽导致变量落错作用域

**犯的错**：修复目标归档的 Rust 借用冲突时，补丁只锚定了通用的 `goals` / `found` 初始化片段，两个归档变量被插入到相邻的目标编辑函数，导致 `cargo check` 失败。

**根本原因**：相邻函数存在高度相似的初始化代码，补丁缺少函数名或归档专属语句作为定位上下文。

**加了什么规则**：
- 修改相邻且结构相似的函数时，补丁上下文必须包含函数签名或业务专属语句。
- 应用补丁后立即读取实际行号片段，再运行编译检查；不能只依赖补丁工具返回成功。
- 编译失败时只修正错误作用域，不顺带重写相邻函数。

### 2026-07-12 程序化生成补丁时残留 diff 标记

**犯的错**：用脚本拼接 Rust 函数补丁时重复添加了 `+` 前缀，导致函数声明以 `+fn` 写入，`cargo check` 才发现语法错误。

**根本原因**：补丁生成逻辑同时在内容和 hunk 层添加新增行标记，只检查了 `apply_patch` 是否成功，没有立即检查写入后的源码语法。

**加了什么规则**：
- 程序化拼接补丁时，只允许一个层级负责 diff 行前缀。
- 手工移动函数边界时不得把示意 hunk 标记 `@@` 写进源码；应用后立即读取实际片段，确认括号和函数边界再继续下一处修改。
- 修改 Rust、TypeScript 或 JavaScript 后，必须立即运行对应编译或构建检查；`apply_patch` 成功不等于源码有效。
- 编译失败时先检查实际写入片段，再做最小修复，不重新生成整段代码。

### 2026-05-31 规则文档散落与 AI 上下文割裂

**犯的错**：以往将各种规范直接放入 `docs/`，或者放入各个 IDE 的专用目录 (`.cursorrules`、`.claude/skills/`等)，导致 AI 上下文碎片化。新增规范后，部分 AI 工具无法实时感知。

**根本原因**：缺乏统一的 AI 资产目录 (SSOT)，以及依靠人力或静态复制而非运行时动态链接，导致多点维护且极易过时。

**加了什么规则**：
- 强制所有环境统一采用 `.ai/rules/` 作为 AI 读取规范的标准目录。
- 严禁手动复制或双写。必须利用操作系统的软链接保持单点数据源。
- 引入了 `scripts/sync-ai-rules.sh`，将其挂载于任何关键生命周期（如体检、初始化时）进行全自动映射。

### 2026-05-31 依赖人力要求 AI 记录经验导致演进缓慢

**犯的错**：原本只依靠 `AGENTS.md` 里的文本约束“犯错后必须记录 LESSONS.md”，实际操作中极易被人类和 AI 遗忘。

**根本原因**：将反思过程当做一种“道德约束”，而没有沉淀为可被低成本唤起的工程“技能”或“引擎”。

**加了什么规则**：
- 构建了全自动引擎：新增 `scripts/auto-reflect.sh`（复盘提取）和 `scripts/optimize-rules.sh`（规则修剪）。

- 注册为 `.ai/skills/` 通用能力，人类只需对 AI 讲“自动反思”，闭环立即发生。

### 2026-07-18 Provider 自定义名称写入后未回读校验

**现象**：用户修改连接名称后，继续开发或重启后界面又显示旧名称，难以判断是浏览器预览未持久化、桌面进程未重启，还是写入路径返回了旧状态。

### 2026-07-18 Preview 与 Tauri Provider 根目录缺少可观测性

**现象**：浏览器预览和桌面端都显示 Provider 配置，但两端出现名称或模型不一致时，界面无法判断它们是否读取了同一个项目目录和同一版文件。

**根本原因**：两端虽然共享 `.project-os/desktop-provider.json` 这一约定，但分别通过 Vite HTTP middleware 和 Tauri Rust command 访问，且此前状态没有来源、工作区根目录或文件版本信息。

- 发现两端状态不一致时，先比较三项元数据，再判断是缓存、进程版本还是项目根目录问题。

### 2026-07-18 额度耗尽不能伪装成网络中断

**现象**：当前模型持续显示“连接不可用”，但网关实际返回的是 `403 insufficient_user_quota`；60 秒自动复测会重复得到同一失败，看起来像网络反复中断。

**根本原因**：健康状态只有 `available / unavailable` 两类，无法区分可重试的网络故障和需要更换 Key/模型的额度故障。

**加了什么规则**：
- Provider 健康状态至少区分 `quota-exhausted` 与一般 `unavailable`。
- Provider 不做分钟级后台连接复测；瞬时网络波动不能在用户无操作时把已验证连接标记为断开。连接状态由显式测试和真实请求证据更新。
- UI 必须展示可行动的原因（额度不足、模型不可用、网络超时），不能统称为网络中断。

### 2026-07-18 模型生成的 unified diff 不能直接信任

**现象**：可用模型成功返回了代码和结构化改动，但其中一份 unified diff 的 hunk 行数与实际新增行数不一致，`git apply --check` 报 `corrupt patch`。

**根本原因**：模型输出是文本建议，不是已经过语法和补丁格式验证的变更；仅凭模型请求成功不能认为任务可以写入。

**加了什么规则**：
- Patch Draft 必须先经过 unified diff 解析和 `git apply --check`，通过后才能进入用户确认。
- Apply 失败必须保留失败证据并生成修复路径，不能部分写入或把模型回复标为成功。
- 真实验收要区分“模型可调用”“草稿可审阅”“补丁可应用”“检查通过”四个终态。

### 2026-07-18 等待用户动作不能恢复为执行中断

**现象**：计划确认后任务已经持久化，并明确停在“等待生成改动”；应用重新加载时，恢复逻辑把它改成“上次处理因应用关闭而中断”，显示失败和重试按钮。

**根本原因**：恢复逻辑只看 `runtimeState=executing`，没有识别最新助手 turn 上仍存在的 `generate-patch` 用户动作；等待确认和真正正在运行的请求共用了同一个持久化状态。

**加了什么规则**：
- 恢复前必须检查最新 turn 是否存在未消费的用户动作；存在“生成改动草稿”等下一步动作时保留执行态，不生成失败恢复 turn。
- 只有没有可继续的用户动作、且请求确实处于处理中时，才标记为应用关闭中断。
- 回归测试必须覆盖“确认后重载”和“真正执行中重载”两种恢复分支。

### 2026-07-18 目标验收签收不能依赖全局旧目标

**现象**：为新目标运行通用签收接口时，验收文件仍指向旧的 Desktop v0.1 目标，签收记录会写入旧目标。

- 新目标验收前必须确认验收契约的 `goal.id` 与当前目标 ID 一致。
- 全局验收报告不能直接签收任意新目标；签收接口需要显式目标 ID 和关联验收证据。

### 2026-07-18 桌面端旧进程导致 Preview 与 Tauri 版本不一致

**现象**：浏览器预览已经移除主列表搜索和归档记录，但桌面端仍显示旧的搜索框和“隐藏已归档”。

**根本原因**：桌面端 `target/debug/OmniDesk` 是更早启动的旧进程，不会随 Vite 热更新；重启 Tauri 时又被残留的 1420 端口 Vite 进程阻塞。

**加了什么规则**：桌面端更新后必须确认 Tauri 进程启动时间和 1420 端口归属；不能只刷新浏览器预览。重启时要一起清理旧的 Vite / Tauri 进程，并验证两端使用同一份最新前端代码。

### 2026-07-18 对话历史长标题覆盖操作区

**现象**：对话标题较长时会延伸到时间、归档或删除图标下方，造成文字和操作控件叠住。

**根本原因**：标题行的时间和操作按钮使用绝对定位，但标题容器没有稳定的右侧占位，也没有允许标题子项正确收缩。

**加了什么规则**：对话历史条必须使用可收缩的标题列、固定的时间列和预留操作区；标题容器设置 `min-width: 0` 与省略策略，不能依赖绝对定位让文本自行避让。

**补充**：隐藏操作默认不预留宽度；只在 hover 或键盘聚焦时收缩标题并显示操作，避免静态状态过早截断标题。

### 2026-07-18 永久删除记录不应被误认为可在历史管理中找回

**现象**：用户删除对话后，在“历史管理”弹窗里找不到对应记录。

**根本原因**：历史管理只收纳可恢复的归档记录；删除动作会从本地存储永久移除，但原来的删除按钮和确认提示没有明确表达“不可恢复”。

**加了什么规则**：对话治理必须明确区分“归档 = 可恢复”和“永久删除 = 不保留记录”。删除按钮、确认提示和历史管理说明都要使用一致的“永久删除”文案。

### 2026-07-18 当前任务与右侧目标使用了不同来源

**现象**：执行计划已经带有“打磨对话体验”的目标关联，但右侧目标区仍显示“暂无进行中目标”。

**根本原因**：右侧栏只读取全局 `activeGoalId`，该值仍指向一个已完成目标，没有优先读取当前对话或当前任务的 `goalId`。

**加了什么规则**：任务详情、对话上下文和右侧目标区同时出现时，优先以当前任务/当前对话的目标关联作为展示上下文；全局活动目标只作为没有任务上下文时的回退。

### 2026-07-18 补丁定位不能只依赖重复代码片段

**现象**：首次补丁误命中了同名的 `activeGoal` 声明，写入了任务创建 helper，而不是右侧栏。

**根本原因**：修改前没有用函数边界确认唯一定位；构建不会捕获未触发路径中的未定义运行时引用。

**加了什么规则**：对存在重复局部声明的文件，补丁必须以函数签名和相邻上下文定位；修改后至少运行覆盖该路径的单元测试或交互验证，不能只依赖构建通过。

### 2026-07-18 对话更新时间不能使用展示格式作为持久化值

**现象**：对话记录持久化为 `HH:mm`，列表排序和“今天 / 昨天 / 更早”分组却按 ISO 时间解析。

**根本原因**：展示格式和存储格式共用了 `updatedAt` 字段，时间失去日期和时区后无法可靠排序。

**加了什么规则**：持久化时间必须使用 ISO 8601；只在展示层按“今天显示时分、过去显示日期”的规则格式化。

### 2026-07-19 目标创建不能拆成多个独立持久化步骤

**现象**：创建阶段目标时，`goals.json` 先保存，再更新 `project-goals.json` 的 `stageGoalIds`。若第二次写入失败，页面会看到未被父项目目标索引的孤立目标。

**根本原因**：跨实体的业务操作被 command 层拆成了两条 Repository 写入，没有共享锁、回滚日志或单个领域操作边界。

**加了什么规则**：目标创建、改绑或删除只允许由 Goal domain service 构造一次 `transaction_with` mutation 集合；Tauri command 只解析输入与项目上下文，不能自行分步写入关联状态。每个跨文件目标操作至少覆盖“所有索引同时更新”和“单一 Repository 事件”回归。

### 2026-07-19 真实补丁评测不能手写 hunk 作为模型结果

**现象**：首次验证模型输出时手写了一份用于 `git apply --check` 的 diff，但 hunk 行数错误，Git 报 `corrupt patch`。

**根本原因**：模型生成的补丁与人工重写的验证补丁混在一起，验证对象不再是模型真实输出。

**加了什么规则**：Agent Eval 必须保存模型原始 diff，再直接运行 `git apply --check`；若为了最小复现创建辅助 diff，也必须明确标记为夹具，不能计入模型的 patchApplicable 指标。

### 2026-07-19 不完整的 hunk 头必须在审批前拒绝

**现象**：真实 Hermes Eval 返回只有 `@@` 的不完整 hunk 头。规范化器此前只检查字符串包含 `@@`，把该行当普通文本传入审批，最终由 `git apply` 才报“没有有效补丁”。

**根本原因**：hunk 扫描只识别 `@@ ` 开头的有效头，没有把其他 `@@` 前缀视为格式错误。

**加了什么规则**：遇到任何 `@@` 前缀都必须进入 hunk 解析；解析失败在创建 approval 前拒绝。真实 Eval 同时保存原始可应用性和规范化结果，不能把下游 Git 失败伪装成模型已产出可审阅草案。

**补充**：Gateway 对 diff 做格式校验时不得使用会改变负载的 `trim()`；必须原样转发或仅补齐一个终止换行。校验层与执行层都要拒绝不完整 hunk，避免一条路径提前拒绝、另一条路径生成无效审批。

### 2026-07-19 模型 hunk 上下文不匹配必须拒绝而非猜测

**现象**：JSON Schema Eval 的模型 diff 采用了不存在于夹具中的多行 `title` 结构。原生归一化器尝试唯一定位旧内容时，对零个候选结果提前取索引，引发 panic。

**根本原因**：`then_some(starts[0])` 会先计算参数，未命中时仍访问空数组；同时缺少“上下文未匹配即拒绝”的显式边界。

**加了什么规则**：补丁归一化必须对候选数安全分支；任何含旧上下文的 hunk，只有在授权文件中唯一匹配后才能重定位或修复计数。无匹配和多匹配都要在审批前返回可读拒绝，不能猜测位置或 panic。

### 2026-07-19 无上下文新增 hunk 不得自动定位

**现象**：测试回归 Eval 返回只有新增行的 hunk，缺少任何原文件上下文。归一化器无法确定插入位置，生成的 header 仍不能被 Git 应用。

**根本原因**：原先允许 `old_body` 为空继续处理，等价于根据模型声称的行号猜测写入位置。

**加了什么规则**：对已有文件的补丁，hunk 至少需要一行删除或上下文行，且旧内容必须在授权文件中唯一匹配；纯新增且无上下文的 hunk 在审批前拒绝。新增文件仍是单独、显式支持的能力，不能由此路径隐式放开。

### 2026-07-20 不能用坐标与系统按键冒充原生 WebView 自动化

**现象**：为了验证原生 OmniDesk 窗口，使用 macOS 坐标点击与键盘事件尝试向对话输入只读请求。WebView 没有获得稳定焦点，输入法将文本变成无意义内容并打开了系统查找框。

**根本原因**：坐标不是稳定的 UI selector，macOS 输入法和 WebView 焦点也不属于可复现的应用交互契约。该路径无法证明按钮、审批或写入流程的真实行为。

**加了什么规则**：原生窗口验收必须使用稳定的 Tauri/WebDriver/应用内测试入口，或由用户在窗口内手动执行后读取运行证据；不得以坐标点击、全局按键或截图观察作为可签收的端到端自动化。出现误输入时保留用户数据，不擅自删除。

### 2026-07-20 原生 Tabs 验收不能依赖 Radix 的内部 value 属性

**现象**：原生终端诊断脚本找不到“终端”工作区标签，误报终端未渲染。

**根本原因**：Radix Tabs 将触发器的值用于生成 `aria-controls` 关联，而不会把 `value` 直接输出为 DOM 属性；旧脚本选择器依赖了不存在的 `value="terminal"`。

**加了什么规则**：原生 UI 验收优先使用稳定的无障碍关联属性（如 `aria-controls`）或可见语义，不依赖组件库内部实现属性。修正选择器后必须重新跑原生诊断，确认终端挂载、xterm 初始化和会话启动证据完整。

### 2026-07-24 活动目标不能成为通用任务的隐式归属

**现象**：普通对话、图片识别和治理建议产生的临时任务，只因工作区存在活动目标，就自动出现在该目标的“任务拆解”中。

**根本原因**：通用任务工厂默认继承 `activeGoalId`，同时 Goal 的 `taskIds` 既表示所有关联任务，又被右栏当作已确认的正式拆解集合，来源和归属两个概念被混在一个字段里。

**加了什么规则**：通用任务默认不关联目标；只有调用方显式提供 `goalId` 才建立归属。Goal 使用独立的 `decompositionTaskIds` 保存用户确认过的拆解结果，`taskIds` 仅保留关联索引。旧目标缺少拆解集合时按空集合处理，不猜测、不删除历史任务；任务删除、改绑和目标合并必须同步维护两个索引。

### 2026-07-24 结构化追问不能占用工程审批或内存会话

**现象**：Agent 在缺少关键参数时，若把追问当作普通文本或暂存于运行中的 Hermes 进程，刷新、重启和重复提交后都会失去边界或误续传。

**根本原因**：用户回答属于交互输入，不是文件写入或检查授权；Hermes ACP 子进程也会在一次请求结束时退出，不能被当作可持久等待的会话。

**加了什么规则**：`ask_user` 必须作为独立 interaction 持久化在 Agent Run checkpoint 中。提交或跳过后只保存受校验的 ToolResult，再从 checkpoint 重新请求模型；相同表单和相同回答幂等，冲突回答拒绝。表单回答不得生成或消费 Patch / Check approval，`awaiting-user-input` 是安全等待态，重启时保留而不标记为中断。普通聊天未接入 Hermes 前不得宣称自动支持该能力。

### 2026-07-24 新增 Eval case 时不能遗漏派生指标语义

**现象**：`ask-user-resume` 已真实完成 checkpoint 续接，但 runner 沿用普通 Patch case 的 `recovered: false`，把恢复成功率错误降为 50%；发布门槛又未比较恢复率，因此工作流仍显示通过。

**根本原因**：新增 case 只校验了交互证据，没有同步审计聚合指标的分母和回退指标集合。

**加了什么规则**：新增或改变 Eval case 的 `expected` 能力时，必须逐项核对对应结果布尔值和聚合分母；发布门槛同时禁止任务成功率、Patch 可应用率、检查通过率与恢复成功率回退。错误指标的真实 artifact 保留作证据，但不能提升为基线。

### 2026-07-25 前端超时不能代替 Runtime 取消

**现象**：长回答在 12 秒时先显示“模型连接未接通”，随后同一请求仍继续流式输出正文，界面同时出现失败结果和生成中的回答。

**根本原因**：前端用 `Promise.race` 结束了等待，却没有取消 Rust 中仍在运行的 Provider 请求；事件监听又只比较 requestId，没有验证请求仍处于 running。

**加了什么规则**：流式请求的首响应、空闲和整体期限只能由 Runtime 统一控制，超时与取消必须销毁网络 Future；前端不能用墙钟 Promise 伪造终态。收到部分正文后中断必须保留部分内容，单轮超时不得修改 Provider 健康状态；所有 delta 在请求终态后必须拒绝。

### 2026-07-25 懒加载模块失败不能拖垮整个工作台

**现象**：旧 Tauri 开发进程仍存活但 Vite 服务已退出时，首次点击终端无法加载动态 chunk，全局错误边界把整个界面替换为崩溃页。

**根本原因**：开发运行缺少前端服务时，已加载页面仍可短暂工作，而尚未加载的终端 chunk 必然失败；终端没有自己的错误隔离边界。

**加了什么规则**：桌面开发必须通过 `npm run dev` 同时监督 Vite 与 Tauri；重型懒加载功能必须具备局部错误边界，单个 chunk 加载失败不能清空对话和工作区。原生验收需覆盖终端模块挂载与 xterm 初始化。
### 2026-07-25 首屏直接渲染演示 fallback 造成假工作区闪烁

**犯的错**：Workspace、Provider 和主题尚未从 Runtime 恢复时，完整工作台已用 `omnidesk-starter`、`gpt-5.4-mini` 和默认深色 token 渲染。

**根本原因**：fallback 数据同时被当作容错契约和首屏可见数据，没有首次 hydration 门槛；主题也在 React 挂载后才异步应用。

**新增规则**：首次 Workspace 和 Provider 恢复完成前只渲染中性启动壳，不展示演示项目、模型或连接；主题优先从本地轻量缓存在 CSS 绘制前恢复。验收必须分别观察刷新首帧与稳定帧。

### 2026-07-25 会话兼容投影不能改写活动时间

**现象**：桌面端每次刷新后，会话列表中的多条记录都会显示为几乎相同的当前时间。

**根本原因**：Rust 持久化的会话 schema 与前端认定的 canonical schema 不一致，前端在每次恢复时都重复执行兼容迁移；保存命令又无条件用当前时间覆盖 `updatedAt`，把一次只读恢复误记成了所有会话的新活动。

**新增规则**：会话契约只能有一个 canonical schema owner；兼容读取和恢复投影不得改变内容活动时间。保存已有记录时必须保留调用方提供的非空 `updatedAt`，刷新、恢复和 schema 投影不得批量改写会话排序依据；旧 schema 兼容必须有覆盖重复刷新与时间保持的回归测试。
