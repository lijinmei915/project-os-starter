## 怎么写一条好的 LESSON

- **犯的错**写用户视角的现象，不要写"代码里少了个参数"这种 PR 描述式复盘
- **根本原因**要深一层：不是"忘了改"，而是"为什么容易忘、哪套系统没兜住"
- **加了什么规则**必须可执行，且明确写进了哪个文档的哪一节；空写"下次注意"无效
- 一条 LESSON 只讲一件事。真的是两个独立问题就拆成两条
