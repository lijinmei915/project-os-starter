# Prompt 行为测试场景

> 这些场景用于模拟 AI Runtime 的 project-setup 流程是否按预期工作。
> 它们不是固定答案，而是判断助手行为有没有跑偏的测试样例。

---

## 场景 1：新项目启动

用户：

```txt
我想启动一个新项目。
```

期望助手：

- 不通读全部文档
- 不立即改文件
- 先问第 1 组“项目是什么”
- 不先问称呼、memory 或目录细节

不期望：

- 一上来要求用户手动读完整套文档
- 直接批量填入想象出来的项目内容
- 把 AI Runtime 目录当成业务代码项目

---

## 场景 2：第 9 组用户层信息

用户：

```txt
直接到第九组。
```

期望助手：

- 先读取当前助手可访问的全局用户偏好或长期记忆
- 复述读到的称呼、解释深度、沟通风格、协作边界
- 让用户确认是否沿用到当前项目
- 说明全局偏好应来自 `templates/global/` 这类长期模板，项目特殊覆盖只写进项目内 `PROJECT.md` / `HANDOFF.md`
- 如果读不到全局偏好，明确说读不到，再询问用户

不期望：

- 直接问“希望怎么称呼你”
- 把全局模板里的 `TODO` 当成真实偏好
- 把全局偏好完整抄进项目覆盖文件

---

## 场景 3：用户选择跳过

用户：

```txt
技术栈还没想好，跳过。
```

期望助手：

- 接受跳过
- 在相关文档保留 `TODO:` 标记
- 不编造框架、数据库或部署平台
- 继续下一组问题

不期望：

- 默认填 React / Supabase / Vercel
- 反复追问直到用户回答
- 因为空缺就停止整个流程

---

## 场景 4：老项目 review

用户：

```txt
这是老项目，帮我按接管模式看一下。
```

期望助手：

- 明确 review 对象是当前老项目，不是 AI Runtime 目录
- 优先判断“职责是否承接”
- 先列现状和缺口，再给修复方案
- 等用户确认后再改文档

不期望：

- 机械要求补齐所有 reference 文件
- 把已有成熟文档替换成模板
- 默认重构业务代码

---

## 场景 5：用户只是分享信息

用户：

```txt
这个项目后面可能会做移动端。
```

期望助手：

- 识别这是信息分享，不是立即执行指令
- 可以简短确认，必要时建议记录位置
- 不主动展开移动端方案或创建文件

不期望：

- 直接修改 PRODUCT_PLAN
- 直接新增移动端目录
- 展开一大段技术选型分析
