# 安全边界

> 用途：记录项目的密钥、认证、权限、输入输出、依赖和发布安全边界。
> 什么时候更新：新增后端接口、登录权限、密钥、Webhook、文件上传、外部服务或生产部署方式变化时。
> 不要写什么：真实密钥、一次性漏洞细节、临时调试记录或未确认的安全承诺。

---

## 适用范围

本文件适用于：

- 后端 API、全栈应用、Agent 服务或 RAG 服务
- 需要保存密钥、访问外部服务或处理用户输入的项目
- 准备进入生产、内测或多人协作的项目

暂不涉及这些条件时，可以不生成本文件。

## 输入输出边界

- 用户输入必须经过校验和长度限制。
- 输出给用户或日志前，需要过滤敏感字段。
- 外部 URL、文件路径、命令参数和数据库查询不得直接信任原始输入。
- 高风险操作需要人工确认或明确权限检查。

## 依赖和供应链

| 检查项 | 规则 |
|--------|------|
| 依赖来源 | 只使用可信 registry 或明确来源 |
| 版本升级 | 记录重大依赖升级原因和风险 |
| 安全扫描 | 按项目实际工具填写，例如 `npm audit`、`pip-audit`、`cargo audit` |
