# 工作区可视化规范

> 用途：定义 OmniDesk 左侧工作区每个菜单下的页面应该怎么可视化、怎么放状态、怎么放动作、怎么处理空态和风险。
> 什么时候更新：工作区菜单职责、页面视觉结构、工作面组件模式或可视化验收规则变化时。
> 不要写什么：单次页面实现流水、临时截图反馈、具体业务文案全文、未确认的新功能路线。

本文是 `项目流程 / 任务执行 / 知识记忆 / 工程资产 / Agent 配置` 下所有工作面的可视化规范。

核心目标：

```txt
每个菜单都必须让用户一眼知道：
当前是什么状态 -> 为什么是这个状态 -> 下一步能做什么 -> 相关证据在哪里
```

---

## 总原则

1. **工作面不是文档页**
   - 不以大段说明文字作为主体。
   - 说明文字只用于解释状态和动作，不替代状态可视化。

2. **每个菜单必须有主视觉结构**
   - 不能只显示 `治理角色 / 状态来源 / 更新时机`。
   - 治理元信息放在页面底部或折叠区域，主区域优先展示真实状态。

3. **先状态，再动作，再证据**
   - 状态在顶部。
   - 主要动作在首屏可见。
   - 证据文件、日志、报告放在底部，可点击预览。

4. **同类菜单同类结构**
   - 生命周期类页面用进度型结构。
   - 任务类页面用任务详情 / 队列结构。
   - 资产类页面用健康矩阵 / 文件列表结构。
   - 配置类页面用连接状态 / 能力矩阵结构。

5. **少卡片、强分区**
   - 页面区域使用全宽分区和栅格。
   - 卡片只用于重复项、任务项、文件项和配置项。
   - 不在卡片里再套卡片。

## 页面骨架

所有菜单工作面使用同一套骨架：

```txt
Workspace Surface
  Header
    Title
    One-line State Summary
    Primary Badge / Status
  State Visual
    Progress / Health / Connection / Queue / Matrix
  Primary Actions
    1-3 个当前可做动作
  Main Content
    最近完成 / 下一步 / 文件状态 / 配置项 / 结果列表
  Evidence
    关联文件、报告、运行记录，可点击只读预览
  Governance Meta
    治理角色、状态来源、更新时机、下一步治理动作
```

规则：

- Header 不超过两行说明。
- State Visual 必须在首屏出现。
- Primary Actions 最多 3 个，更多放入 `高级详情` 或二级菜单。
- Evidence 必须可点击，只读预览，不直接编辑。
- Governance Meta 不能占据页面主视觉。

## 工作面类型

### 1. Progress Surface

适用：

- `项目流程 / 当前进度`
- `定义目标 / 当前目标`
- `验证交付 / 验收报告`
- `复盘沉淀 / 交接记录`

结构：

```txt
阶段 / 状态标题
进度数值 + 进度条
关键指标 3-4 个
最近完成
下一步
依据文件 / 证据
```

必须包含：

- 当前阶段或当前目标
- 百分比或状态进度
- `最近完成`
- `下一步`
- `进度依据`

交互：

- 点击下一步任务进入任务详情。
- 点击需关注筛选风险项。
- 点击依据文件展开只读预览。

禁止：

- 用大号百分比替代所有状态解释。
- 空的“最近完成”留大块空白。
- 将进度依据做成不可点击标签。

### 2. Task Surface

适用：

- `任务执行 / 当前任务`
- 从 `当前进度` 点击任务后的任务详情
- `任务执行 / Patch 草案`
- `任务执行 / 执行结果`

结构：

```txt
任务标题 + 状态
返回上级入口
主操作按钮
计划摘要
影响范围
验证方式
高级详情
```

必须包含：

- 任务短标题
- 状态 badge
- 返回来源，例如 `返回当前进度`
- 主操作：`生成改动 / 应用改动 / 运行检查 / 更新交接`
- 计划摘要：做什么、看什么、改哪里、怎么验

交互：

- 任务 tab 标题必须显示任务名，不使用抽象 `执行`。
- 主操作必须首屏可见。
- 技术日志、Diff、完整检查输出放入 `高级详情`。

禁止：

- 把主要操作藏在 `更多操作` 里。
- 用内部名如 `execution`、`runner`、`patch draft` 作为用户主标题。
- 任务详情没有返回路径。

### 3. Health Surface

适用：

- `工程资产 / 治理文件`
- `项目流程 / 设计实现`
- `工程资产 / Schema`
- `工程资产 / 报告产物`

结构：

```txt
健康结论
状态矩阵：正常 / 本地变更 / 缺失 / 可能过期
建议动作
文件列表
文件预览
生成治理任务
```

必须包含：

- 健康结论
- 分类统计
- 建议处理顺序
- 可点击文件
- 可生成治理任务的动作入口

交互：

- 点击状态卡筛选文件。
- 点击文件只读预览。
- 点击生成任务进入任务闭环。

禁止：

- 只列文件路径，不说明状态。
- 把缺失、过期、本地变更混在一个列表里。
- 文件状态不可筛选。

### 4. Configuration Surface

适用：

- `Agent 配置 / 模型连接`
- `Agent 配置 / 工具白名单`
- `Agent 配置 / Skill 能力`
- `Agent 配置 / 适配器`
- `Agent 配置 / 安全边界`

结构：

```txt
可用性结论
连接 / 权限 / 能力矩阵
当前配置
不可用原因
修复动作
关联文件
```

必须包含：

- 当前是否可用
- 不可用原因
- 配置来源
- 修复或测试动作

交互：

- 模型连接可测试。
- 工具白名单可查看允许项和禁止项。
- Skill / 适配器可查看来源和能力边界。
- 不可用项可生成配置修复任务。

禁止：

- 只显示配置 JSON 或文件路径。
- 把安全边界隐藏到文档里。
- 不说明为什么不能执行。

### 5. Memory Surface

适用：

- `知识记忆 / 项目事实`
- `知识记忆 / 用户偏好`
- `知识记忆 / 长期记忆`
- `知识记忆 / 会话摘要`

结构：

```txt
记忆类型
可信度 / 新鲜度
事实列表
来源
可沉淀项
过期项
```

必须包含：

- 信息类型
- 来源和可信度
- 最近更新时间或新鲜度
- 是否可沉淀 / 是否需要确认

交互：

- 点击来源查看证据。
- 可沉淀项生成确认任务。
- 过期项生成同步任务。

禁止：

- 把长期记忆、当前任务和对话摘要混在一个列表里。
- 未确认信息直接标为事实。

## 视觉层级

### Header

- 标题使用 `--desktop-text-title` 或现有 section title token。
- 状态摘要使用正文大小，不使用 hero 字号。
- 右侧 badge 只放当前状态，不放多个按钮。

### 指标

- 数字不得超过 `30px`，除非是单一核心评分。
- 0 值必须解释含义，例如 `0% / 任务完成度`。
- 指标卡最多 4 个。
- 指标卡可点击时必须有 hover 和 active 态。

### 列表

- 任务列表使用密集列表，不使用大营销卡。
- 每项必须有标题和状态 / meta。
- 可点击项必须有明确 hover。
- 禁用项不能看起来像主操作。

### Evidence

- 文件、报告、记录使用 chip/button 形态。
- chip 必须可点击或明确 disabled。
- 点击后在当前工作面下方展开只读预览。
- 目录和通配符必须提示不能直接预览。

## 状态规则

每个工作面必须覆盖：

| 状态 | 要求 |
|------|------|
| 默认态 | 展示真实数据和主动作 |
| 加载态 | 保留布局，显示轻量加载文案 |
| 空态 | 说明为什么为空，以及下一步 |
| 错误态 | 说明影响、原因和修复入口 |
| 只读态 | 明确“只读预览”，不出现编辑暗示 |
| 可行动态 | 主按钮可见，动作说明清楚 |
| 完成态 | 显示完成证据和下一步 |

## 菜单映射

| 一级菜单 | 默认 Surface | 说明 |
|----------|--------------|------|
| 项目流程 | Progress / Health | 生命周期、目标、规则、设计实现、验证和复盘 |
| 任务执行 | Task | 当前任务、队列、Patch、终端和结果 |
| 知识记忆 | Memory | 项目事实、偏好、长期记忆和会话摘要 |
| 工程资产 | Health | 工程文件、治理文件、报告、Schema、模板 |
| Agent 配置 | Configuration | 模型、工具、Skill、适配器、安全边界 |

---

## 验收清单

实现任何菜单工作面时，收尾必须检查：

1. 首屏是否能看出当前状态？
2. 是否有 1-3 个明确主动作？
3. 是否有可点击证据？
4. 空态是否说明下一步？
5. 错误态是否说明原因和修复入口？
6. 治理元信息是否没有喧宾夺主？
7. 是否使用 `desktop/src/styles.css` 的 token，而不是散落硬编码？
8. 是否在窄屏下不重叠、不截断关键动作？
9. 是否能从页面动作进入任务闭环？
10. 是否避免内部工程词作为用户主标题？
